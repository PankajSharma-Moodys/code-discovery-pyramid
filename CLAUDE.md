## Documentation Standards

Keep planning/design documents (PLAN.md, RESEARCH.md) concise and enforce explicit size/length budgets before writing; if a doc exceeds the budget, trim before presenting it as done.

## Debugging Process

When investigating performance issues or bugs, gather empirical evidence (profiling, timing, logs) before proposing root causes or fixes; do not theorize without data.

## Working Mode / Scope Discipline

Stay strictly within the requested scope during research/design/planning phases—do not write implementation code, benchmarks, or read source unless explicitly asked.

## Quality/Verification Standards

Verify claims (statistics, architecture descriptions, secondhand technical facts) against primary sources before including them in documents or decisions.
